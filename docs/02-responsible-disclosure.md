# 2. 有责任的披露

## 这是一份什么样的披露

这里披露的不是一个可以拿来攻击用户或数盟系统的漏洞，而是一个广泛分发的 SDK **实际做了什么**。受影响的是终端用户的知情权。所以本仓库的目标是让用户、宿主 App 开发者和研究者能看清并核实这些行为，而不是提供可以利用的东西。

## 我们遵守的原则

1. **只分析客户端。** 我们没有攻击、扫描或探测数盟的服务器，也没有尝试访问任何不属于我们的数据。
2. **不使用真实用户数据。** 动态分析全部在模拟设备上进行（见 [4.3](04-tools.md#43-unidbg-harness)）。仓库中的所有示例 payload 都来自一台虚构的设备。
3. **尽量少地接触真实服务器。** 分析早期（2026-10-16），我们曾把模拟设备的上报转发给数盟服务器约 10 次，用来确认服务器会不会对它发 ID。此后再没有发送过，发布版的 harness 中也已删除这条路径。DuClient 只在使用者自己的设备上、以使用者本人的名义，发送比官方 SDK 少得多的字段。
4. **能核对。** 每条结论都给出 `sub_xxxxx` 位置，附带样本哈希和工具，读者可以不信任我们，自己验证。
5. **事实与推断分开。** 客户端行为是事实；服务端如何使用数据、对用户意味着什么是推断，第 6 章会逐处标注。

## 刻意没有公开的内容

| 内容 | 原因 |
|---|---|
| 酷安的数盟 `apiKey` | 这是数盟分配给特定客户的凭证。公开它会让任何人都能以该客户的名义提交上报。所有文件中都已替换为 `<COOLAPK_APIKEY>` |
| harness 的“转发到真实服务器”功能 | 避免有人用模拟设备批量向真实服务器提交伪造数据 |
| 独立的上报伪造脚本 | 同上 |
| 宿主 APK 和签名证书文件 | 版权与无关性。证书可以按 [4.3](04-tools.md#43-unidbg-harness) 的方法自行从 APK 提取 |
| 任何真实设备、真实账号的数据 | 隐私 |

**确实公开了的**：

- `libdu.so` 样本本身，供独立验证用；
- 上报协议的编码方式和传输层的固定 XOR 密钥。有了它们，任何人都能解开**自己设备**发出的流量，看清 SDK 到底上传了什么。我们认为这对用户的知情权是必要的。这些信息本来就内置在每一份分发出去的 SDK 里，DuClient 也早已公开。

## 关于宿主 App

本仓库的样本取自酷安客户端，因为这是我们接触到它的途径。但这里讨论的是**数字联盟 SDK 的行为**，而不是酷安的行为。同一个 SDK 被许多 App 集成，各个宿主的配置可能不同（例如是否关闭 IMEI 采集、是否开启应用列表）。酷安传给 SDK 的配置见 [5.1](05-libdu-behavior.md#51-结构与通信)。

## 法律与使用

- 本项目的逆向分析以互操作（让第三方客户端以最少的数据完成设备注册）和安全隐私研究为目的。
- `sample/libdu.so` 的版权属于北京数字联盟网络科技有限公司。收录它只是为了验证，不授予任何使用许可。
- 文中对相关法规、标准的引用（例如数盟隐私政策中自己列出的《个人信息保护法》、GB/T 41391-2022），只是为了说明对照依据，不构成法律意见。是否合规，应由主管部门判断。
