# 6. 数字联盟：一个设备 ID 背后意味着什么

第 5 章是我们在客户端看到的事实。这一章把这些事实和数字联盟（北京数字联盟网络科技有限公司，下称“数盟”）公开的自我介绍、隐私政策放在一起看，再推断这套系统可能怎样运转。

**本章所有关于服务端的内容都是推断。** 我们看不到数盟的服务器，也不知道哪个客户查询过什么。推断的依据是客户端上报了什么，以及数盟自己说了什么。

## 6.2 隐私政策的说法与我们的观察

数盟隐私政策（2026-07-02 版）中确实列出了不少我们观察到的采集项：设备基本信息、ANDROID_ID、Boot_ID、OAID、DRM 设备标识、网络与 Wi-Fi 信息、代理 / VPN 状态、传感器、应用列表（可配置）、模拟器 / Root / Hook / 多开检测、USB 状态等。这些与第 5 章一致，我们不认为它们构成“未披露”。

下表只列**政策的表述与客户端行为对不上**，或政策**没有提到**的部分。

| 政策原文 | 我们在客户端看到的 |
|---|---|
| “从客户端收集到数据后，于客户端本地进行删除去位的脱敏处理，确保数据无法关联识别” | 绝大多数字段只做了字符 +1 和重排（[5.2](05-libdu-behavior.md#52-字段编码)），完全可逆。IP 地址、DNS、hosts 文件、Wi-Fi 网关等以原值或可逆形式上报 |
| “服务端收到的数据与原始数据完全不存在任何对应关系，即服务器不收集任何设备原始数据” | ANDROID_ID 由 `foO` + `sfOo` 可以完整还原；Widevine 设备 ID（`6yY`）原样上报 |
| “对于收集的设备唯一标识码类信息，我们采用技术手段将原始的不可变更标识符转化为可变更状态，不留存任何不可变更的标识码信息” | 客户端上报的是原值：Widevine ID、ANDROID_ID、eMMC / SoC 序列号（`p1m`、`dJs`、`GZY`，可逆编码）。服务端是否“留存”我们无法验证，但“转化”没有发生在客户端 |
| IMEI、IMSI、MEID、SN、MAC、ICCID：“仅检测上述标识符在当前系统版本下的可获取性及格式合规性……不存储任何原始标识符值，仅记录检测结果的风险评分” | 客户端在能读到时上报的是值本身（`p92`、`3J5`、`Yko`、`dj3`、`41j`，模式 10，可还原）。不仅如此，`fM0` 还会在系统给出随机 MAC 时，主动用 wlan1 / p2p0 的地址**反推出厂 MAC**。这超出了“检测可获取性”的范围 |
| 应用列表：“应用信息在客户端本地完成不可逆加密后上传，服务端仅进行加密哈希比对” | 内置名单（Root、Hook、脚本工具）确实只在本地比对、上报结果，这一点相符。但另有：微信、支付宝、QQ 的首次安装时间（`mbU`），微信 APK 路径（`ZQM`），宿主安装来源（`T2t`），**当前有网络连接的 App**（`6PH`，解析 `/proc/net/tcp*`），`ps` 进程列表（`OW2`），已启用无障碍服务的**包名**（`yzW`，可逆） |
| “不收集用户行为信息” | 是否正在录屏（`psg`）、屏幕是否亮着（`NAB` / `sCc`）、哪些 App 正在联网（`6PH`），以及持续的传感器、信号强度、蓝牙扫描事件接口（[5.8](05-libdu-behavior.md#58-事件接口)）。这些算不算“行为信息”可以讨论，但政策里没有提到 |
| “收集完成后便会自动关闭退出，不进行后台自启动和关联启动……整个过程一般持续数秒” / 不驻留：“仅……于用户首次运行App时收集信息” | 每次 `query` 都会发送 mdna。SDK 自己维护启动计数 `boot_times`；后续上报由服务器下发的间隔调度（[5.9](05-libdu-behavior.md#59-服务器对采集的调度)）；native 层有持续事件的处理函数。这些都说明它不是“只在首次运行时收集一次” |
| 政策未提及 | **hosts 文件内容**（`YWu`）、**用户安装的 CA 证书**（`Q23`）、**其他公司 SDK 的设备 ID**（百度、数美、阿里 UTDID、字节 AppLog、穿山甲、`..ccvid`、`zx.db`）、**局域网邻居的 IP 和 MAC**（`9P6`）、周围 Wi-Fi 扫描结果（`Dg1`，政策只列了当前 Wi-Fi 的 SSID / BSSID / 网关）、**已配对蓝牙设备**和附近蓝牙设备扫描（政策写的是“获取蓝牙信息，以关联双方数据”）、**写在共享存储上的跨应用 ID**（`/sdcard/.o_a`，[5.7](05-libdu-behavior.md#57-跨应用-id-与其他-sdk-的-id)） |

政策中“我们不会对外提供原始设备唯一标识符、原始应用列表、原始网络信息”“去标识化设备信息最长 6 个月”等关于服务端的承诺，我们无法从客户端验证，所以不做评价。

## 6.3 推断：一个 ID 能告诉别人什么

把第 5 章的事实连起来：

1. **ID 是跨应用、跨重装稳定的。** 服务器同时拿到 Widevine ID、可还原的 ANDROID_ID、文件系统和硬件指纹、共享存储上的 `o_a`、其他 SDK 的设备 ID，以及“prefs 被恢复到新安装里”这样的信号。数盟自己也说要“为每台移动设备颁发设备更可信ID”，提供“设备跨平台ID及不同ID之间的对应关系”。所以同一台手机上，不同 App 拿到的数盟 ID，在数盟那边大概率会被归到同一台设备。
2. **每一次上报都附带一份设备环境快照**：Root、Hook 框架、调试器、抓包证书、TLS 校验是否被改、VPN、开发者选项、ADB、SELinux、无障碍服务、hosts 屏蔽了什么、授予了哪些权限、数据目录能不能读……
3. **数盟说它保存“该设备的历史风险标签”**，并以“设备风险评分、异常类型、设备环境真实性判断”的形式返回给接入方。这是隐私政策自己的说法。

由此推断：

> 一个 App 只要拿到你的数盟 ID，向数盟查询一次，就可能知道这台设备有没有 Root、装没装 Hook 框架、hosts 里屏蔽了什么、有没有装抓包证书、给没给权限。
>
> 你可以在这个 App 里把 Root 和 Hook 藏得很好，但这没有意义：它只需要看看你的 ID，再看看这个 ID 在其他 App 上的上报记录，只要你在其中某一个 App 里没藏住就够了。

换句话说，隐藏环境这件事从“对每个 App 分别隐藏”变成了“必须对所有接入了数盟 SDK 的 App 同时隐藏，而且在过去的每一次上报里都没出过错”。数盟宣称的覆盖规模是“9.47 亿+ 近 6 个月内活跃设备”“46+ TOP100 级 APP”。

网络这一层也类似。上报里有当前 Wi-Fi 的 BSSID（路由器 MAC）、局域网邻居表、周围 Wi-Fi 扫描结果、已配对和附近的蓝牙设备。结合数盟的“全域设备与网络的关联关系”“对特定设备特定网络实时关联扩展”“设备-list扩展 / WiFi-list扩展”，可以推断：一台设备被标记为“有风险”之后，和它连过同一个路由器、出现在同一个局域网或蓝牙范围内的其他设备，也可能被“关联扩展”。

我们不知道哪些接入方实际这样使用数据，也不知道数盟的模型怎样给不同信号加权。但这套采集的设计（全量环境快照 + 跨应用稳定 ID + 网络关联）**足以支撑**上面的用法，而数盟的公开材料描述的正是这种能力。

## 6.4 为什么值得关注

- **用户没法重置。** 恢复出厂以外，用户能清掉的只有 App 数据。Widevine ID、硬件序列号、文件系统指纹、共享存储上的 `.o_a` 都不受影响。
- **用户看不见。** 宿主 App 的隐私政策里通常只写一句“集成了数字联盟可信 ID SDK”，用户不会知道这意味着 hosts 文件、CA 证书、局域网邻居会被发出去。
- **受影响最大的恰恰是在意隐私的人。** 用 hosts 屏蔽跟踪域名、装证书检查流量、用 Root 管理权限、用 Hook 框架阻止追踪，这些行为本身就会被记成“风险”，并跟着 ID 走到所有接入了 SDK 的 App 里。
- **“风控”和“标识”是同一件事。** 数盟首页把“识别设备唯一”和“判断设备风险”并列为产品的“关键能力和价值”。跨应用稳定标识的能力，本来就是它卖的东西。

## 6.5 对普通用户和开发者

**用户**能做的有限，但有几件事是确定有效的：

- 拒绝 App 的电话、定位、附近设备、蓝牙权限，可以挡住 IMEI / IMSI / ICCID、Wi-Fi 扫描、蓝牙设备等相当一部分采集（[5.6](05-libdu-behavior.md#56-后续上报设备信息全量采集)）；
- 删除共享存储上的 `/sdcard/.o_a`、`/sdcard/Android/Data/System/local/`（`o_a`、`.ccvid`）、`/sdcard/Android/ZHVzY2Lk`、`/sdcard/..ccvid`，可以切断经由共享存储的跨应用关联（App 下一次拿到 `o_a` 时可能会重新写入）；
- 要清楚的是：只在某一个 App 里隐藏 Root / Hook 并不能避免被标记，见 6.3。

**集成了数盟 SDK 的开发者**：

- 本版本 SDK 有关闭部分采集的开关：`DUHelper.mMeic` 可以关闭 IMEI / DeviceId 读取，另有配置可以关闭共享存储 `o_a` 的读写（`data_163418 == 0x2718`）和 `mch`（`data_14ab5c == 0x2714`），具体对应哪个配置项需要查阅数盟的集成文档；
- 数盟隐私政策要求接入方“在App首次启动或首次调用本SDK功能时，通过弹窗或其他显著方式向用户单独告知本SDK的存在及其信息收集行为，并获得用户的明示同意”。第 5 章可以作为告知内容的参考。

## 6.6 我们不知道的

- 服务器如何计算风险、返回给接入方的具体是什么、数据保存多久；
- 哪些接入方会查询哪些设备；
- SDK 的 Java 层做了什么，包括事件监听何时注册、21 个厂商 ID 从哪里来；
- 其他版本的 SDK、其他宿主 App 的配置有何不同。
